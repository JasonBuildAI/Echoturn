# 选型优势：Echoturn 强在哪，以及什么时候该用别的

**English: [positioning.md](positioning.md)** —— 英文版是唯一真源，本页是它的中文对照。
两版不一致时以英文版为准；改英文版时要同一个 commit 改这一页。

Echoturn 是**故意做小**的。这一页把边界写下来：它比别的方案强在哪、它干脆不做什么，
以及当答案不是 Echoturn 时该去用哪个项目。

**快照日期 2026-09-21**：下面的星标数与价目都是那一天的样子。引用它们**必须带上日期**；
数字变了就改这一页，别在别处再抄一份。

## 1. 这是什么

一条与供应商无关的实时语音对话流水线，从一个已经端到端跑通的语音助手里提炼出来：
采集、断句、ASR、LLM、攒句合成、有序播放、取消与插话。

- `src/echoturn/` 下约 5,200 行 Python，目标是让人**一口气读完**。
  核心安装只需要一个依赖 `httpx`。
- 七个事件就是全部公开契约（`ack`、`sentence`、`audio`、`sink`、`aborted`、`done`、`error`），
  线上契约见 [events.zh-CN.md](events.zh-CN.md)。
- FastAPI / SSE 那座桥只有一个可选文件。流水线里没有任何一处 import Web 框架，
  也不会去开一个你没要求的连接。

## 2. 它故意不做什么

这些不是「待补齐的缺口」，而是这个库能小到可读、能安分地待在一个已有主见的产品下面的原因。

| 不含 | 为什么 |
|---|---|
| 长期记忆、人设、提示词策略 | **给模型看什么由宿主决定**。一个顺手把记忆也管了的库，会和你已经建好的记忆层打架。 |
| 账号、配额、计费、运维台 | 那是产品决定，不是流水线决定。 |
| WebRTC、电话接入、多人房间 | 那是更大那几家的真本事（见第 4 节），也是另一类工作。 |
| 流式中间转写 | Echoturn 收的是一句**说完的话**。中间结果属于传输层与供应商，流水线两种情况下是同一条。 |
| 落盘、埋点、任何往外打电话的动作 | 一轮对话不应该产生一个你看不见的文件或网络请求。 |
| 厂商专属适配器 | 一个 OpenAI 兼容适配器 + mock。接某个厂商的端点是一个小继承类，不是一次发版。 |

## 3. 它真正更强的地方

| 优势 | 落到实处的意思 |
|---|---|
| 核心只有一个依赖 | 没有 Web 框架、没有 ORM、没有运行时、不需要账号。`[dsp]`、`[vad]`、`[web]`、`[cli]` 都是你自己决定要不要装的额外件。 |
| 契约小到可以照搬 | 七个事件，逐字段有文档。传输你自己选：浏览器 demo 与终端 demo 只是同一个生成器的两个宿主。 |
| 断句敢承认自己在猜 | 说完判定同时量「真正的人声有多长」与「这句说完了吗」，只有在不得不时才回落到静音截止时间；可选模型不在时，构造函数会在**返回值里明说**，而不是悄悄降级。 |
| 插话不吞掉用户的话 | 她还在合成时你开口，你说的那句会成为下一轮的开头；播放还会对照她自己的回声做门控，不让她打断自己。 |
| 音频不可能乱序 | 合成天然乱序完成，播放严格按片序号排序，不跳、不叠、不交叉。 |
| 首声不等最后一个 token | 模型还在写，文本就一小段一小段送去合成。`python bench/latency.py --compare` 会在**你自己的机器上**把这个收益量成一个数 —— 也包括「攒句反而更慢」的那一档。 |
| 从构造上就能离线 | mock 的 ASR / LLM / TTS 能把整条流水线跑完，不要 Key、不联网、不下模型；CI 在三个 Python 版本上跑，不带任何密钥。 |
| 护栏都证明过会失败 | 发布前的隐私检查带 `--self-test`，喂一段必须被抓住的文本；文档链接检查会因为一个不存在的页面变红。**做不红的护栏不算护栏。** |
| 所有阈值只有一张表 | 每个阈值都在 `echoturn.config.DIALS` 里，调用时现读环境变量，并且有测试拿 [tuning.zh-CN.md](tuning.zh-CN.md) 和它对账。 |

## 4. 诚实的横向对比

数字是 2026-09-21 的快照。那几家不只是更大，而是在一些**对产品很要紧**的地方走得更远；
这张表就是让你睁着眼选它们。

| 项目 | 2026-09-21 快照 | 强在哪 | 它给不了你、而 Echoturn 给的 |
|---|---|---|---|
| [huggingface/speech-to-speech](https://github.com/huggingface/speech-to-speech) | 13,290★ / 1,684 fork，Apache-2.0，创建于 2024-08-07，PyPI `1.0.0`（2026-09-06）；README 自述是数千台 Reachy Mini 机器人的对话后端 | 一套自带电池的本地栈：VAD、流式 STT、LLM、TTS 串起来，用 OpenAI Realtime GA 事件集（WebSocket 与 WebRTC）对外服务 | 一个能嵌进你自己进程、用你自己事件契约的流水线；只依赖一个库的核心；它不替你对记忆与人设表态 —— **它是一个服务端，不是一个库** |
| [pipecat-ai/pipecat](https://github.com/pipecat-ai/pipecat) | 15,726★ / 2,726 fork | 编排框架：服务生态大、支持多智能体、带客户端 SDK | 一条能读得完的单轮路径。Echoturn 是你拿来**读懂**一轮怎么做的东西，不是拿来接四十家供应商的 |
| [livekit/agents](https://github.com/livekit/agents) | 14,297★ / 3,765 fork | WebRTC 传输、SIP 电话接入、任务调度、规模 | 传输。Echoturn 没有 WebRTC、没有电话；你要一个电话号码，就该用这个项目，而不是这一个 |
| OpenAI Realtime（托管） | 官方价目（2026-09-21）：音频输入 $32 / 1M、输出 $64 / 1M token（`gpt-realtime-2.1`；mini 档 $10 / $20），文本 $4 / $24；`gpt-live-1` 语音会话 $0.05/分钟，且后端模型与工具调用另计 | 原生全双工、原生打断，零运维 | 你自己的供应商、你自己的成本结构（第 6 节）、你自己的传输，还有一条能在 CI 里离线跑的流水线 |

如果今天就要选，答案往往是「选它们」：要电话号码、要一个不是自己写的浏览器传输、
要四十个集成、要一台自己永远不碰的服务器 —— 那就选它们。Echoturn 服务的是另一种情况：
**对话这一层是你自己的**，而流水线是你不愿意再写一遍的那部分。

## 5. 谁都领先不了的那一块：说完判定

「这句说完了吗」这个模型**不是**差异点，这一页不装成是。Hugging Face 那套在
`src/speech_to_speech/VAD/smart_turn.py` 里加载的是 `pipecat-ai/smart-turn-v3` 的 v3.2；
Echoturn 那个可选的端点模型是**同一个仓库、同一个版本**，由 `echoturn-fetch-models` 拉下来。

差别在围绕它的工程深度。他们的 speculative turn 机制比 Echoturn 那两个旋钮更细：
一轮还没说完时先不启动 STT 与 LLM，语音恢复时把这一轮当成新的 revision 重开、
丢掉上一版的输出。这是真优势，值得抄。

## 6. 成本结构：按需计费 vs 按秒燃烧

级联的账是**有内容才付**：有声音才转写、有字才合成，走的是你已有的供应商价目。
端到端音频会话的账是**把整段对话当音频 token 计费**，包括没有新内容的那几秒。

按上面 2026-09-21 的官方价目：同模型的音频 token 输入价是文本输入价的 8 倍，
输出价约为文本输出价的 3 倍。**缓存的音频输入很便宜**（$0.40 / 1M），
所以回放的历史不会滚成雪球；累积起来的是**双方新说出来的每一秒**。

选之前先替你自己算一遍：

```
每天音频分钟数  x  $0.06-0.17（双向每分钟）  =  每人每天的成本
```

这个每分钟区间是**估算**，不是实测：厂商公布的是 token 单价，换算取决于音频的 token 化速率
（这一页按 10–30 token/秒 假设）。请按你自己的通话长度算，并把结果当成数量级而不是报价。
**短促、断续的对话**两种结构可能相差不大；**长时间常开麦**则完全不是一回事。

## 7. 现状，以及还没做完的部分

- 早期软件，一位维护者，没有生产部署，也没有下游用户。[CHANGELOG.md](../CHANGELOG.md) 是诚实的记录。
- 离线套件跑的是 mock 供应商。真实 ASR / LLM / TTS 链路**没有端到端评测**：
  没有 WER、没有 MOS、也没有和基线的对比。
- 没有 WebRTC、没有电话接入、没有流式中间转写：浏览器 demo 提交的是一整段录完的音频。
- 能量 VAD 的门限是**起点而不是实测值**，[turn-taking.zh-CN.md](turn-taking.zh-CN.md) 在那个数定义的地方就写明了；
  延迟数字必须用 `bench/latency.py` 在你自己的机器上量。
