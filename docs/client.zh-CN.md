# 浏览器客户端

**English: [client.md](client.md)** —— 英文版是唯一真源，本页是它的中文对照。
两版不一致时以英文版为准；改英文版时要同一个 commit 改这一页。

`clients/` 是一组 ES 模块，**没有构建步骤**。页面直接 import：

```html
<script type="module">
  import { Call } from "/client/echoturn-client.js";
</script>
```

`worklet.js` 必须和加载它的模块放在一起 —— `mic.js` 是相对自己的 URL 去解析那个 processor 的
—— 所以把整个目录拷过去就够了，从子目录提供服务的宿主不需要配置任何东西。

## 两种用法

**`Call` 就是整场对话**：麦克风、有序播放、字幕，以及中间那三个判断。只想要一通语音通话的
页面，需要的就是这一个导出。

**其余的是它的零件**，因为一个已经有自己的会话状态、自己的播放器、自己的麦克风处理的页面，
应该能只拿它要的那一块。这些模块自己不带状态，所以混用它们不等于把任何东西实现了第二遍。

## 模块

| 模块 | 是什么 |
|---|---|
| `worklet.js` | AudioWorklet processor：一块采样，以及它的音量 |
| `mic.js` | 打开一条麦克风流，带一条回落路径 |
| `levels.js` | 人声地板、噪声参考、百分位 |
| `echo.js` | 回复经过麦克风回来有多响 |
| `interrupt.js` | 要求音量先持续住，才算一次打断 |
| `cursor.js` | 一个停顿意味着什么：留着、问、发、丢 |
| `ring.js` | 有界的帧缓冲，以及留存的尾巴 |
| `queue.js` | 按序解码并播放，接缝为零 |
| `wav.js` | 帧 → 16 kHz 单声道 WAV |
| `base64.js` | 一份 base64 实现，长音频分片处理 |
| `stream.js` | 从流式响应里读出一轮的事件 |
| `dials.js` | 设置，以及服务端回答之前先用什么 |
| `call.js` | 上面这些之间的接线 |
| `echoturn-client.js` | 重新导出它们的入口 |

## 一次通话，从头到尾

```js
const call = new Call({
  session: "demo",
  onTurn: (text) => show("you", text),
  onSubtitle: (sentence, i) => show("her", sentence, i),
  onState: (state) => label(state),
  onNotice: (text) => note(text),
});

button.onclick = () => call.start();     // 音频上下文需要的那一次用户动作
call.say("hello");                        // 也可以打字代替说话
call.setMuted(true);                      // 停止聆听，但通话还在
call.interrupt();                         // 打断回复
call.stop();                              // 关掉麦克风
```

`start()` 会从 `/config` 取设置并打开麦克风；麦克风拒绝时它返回 false，并且已经通过
`onNotice` 说明了原因。

## 它报告的状态

| 状态 | 含义 |
|---|---|
| `idle` | 什么都没发生 |
| `listening` | 麦克风开着，正在听一个人 |
| `thinking` | 有一轮在跑，还没有声音回来 |
| `speaking` | 回复听得见 |

`speaking` 先于 `thinking` 被检查，而且它说的是**声音**，不是请求。一条回复的最后一片，在
请求它的那条流结束之后还会从扬声器里往外走一秒以上；只问「这一轮结束了没有」的客户端，会把
自己的回复当成静音 —— 在外放下，它会把自己正在说的话的尾巴录下来，然后去回答它。

## 看起来像两个的三个状态

`busy`、`capturing` 和 `ending` 是三件不同的事，而麦克风在这三个期间都是开着的。正在跑的一轮
不是一段已经停下的录音，正在被转写的录音也不是一轮。把它们中的任意两个合并，就会丢掉中间
说过的音频 —— 这种故障，听者描述成「她没在听我说话」。

## 这里不存任何阈值

`dials.js` 为每个数字带了一份回落值，它只在 `/config` 回答之前被用到。之后客户端读的是服务端
那张表。

要点就在这里：一个自带 `barge_ratio` 副本的页面，会在服务端改过之后继续用它，而两边单独看都
是对的。回落值的存在，只是为了让「第一个请求就失败」的页面还有东西可用，它的取值就是服务端
发布的那一套。

不是数字的值会回落，**空值**也会 —— 否则它会以 0 的形式到达，通过每一道「是不是有限数」的
检查，然后把它所属的那个阈值静音掉。没有回落值的键会抛异常，因为那是调用方的错误，不是该被
吸收的东西。

## 播放

`queue.js` 让每一片在前一片结束的位置起播，按音频时钟排期，所以接缝是采样级精确的，而不取决
于一个新元素加载得多快。提前量是 `LEAD_SEC`（15 ms）：正好「现在」起播是一场时钟通常会赢的
赛跑，而从过去起播的音源会从半采样处开始，或者干脆不出声。

解码在片到达那一刻就开始，不排在自己那一轮的后面。慢的是解码，它可能乱序完成，把它压在上一片
的播放后面，等于把它的全部开销加进句子之间的空隙。

`stop()` 会抬高一个代号，于是还在解码的片会在出厂路上被丢掉，而不是在打断之后被播出来 ——
一条已经停掉的回复，就是这样又说了两句话。

## 采集

`mic.js` 一次只开一条流。申请麦克风是异步的，还会弹出一个可能卡住好几秒的授权提示；在那个
窗口里点第二下，会开出**第二条**流，它覆盖第一条，并让第一条继续跑着而没有任何人拿着引用去
停它。症状是录音指示灯一直亮着，界面上却没有任何东西能把它关掉。

被拒绝不会被记住：一次被缓存的拒绝会交给之后每一个调用方，于是一次拒绝就变成永久，按钮看
起来坏了，直到页面被刷新。

实际走的是 AudioWorklet，而回落到 `ScriptProcessorNode` 不是偏好问题 —— 在某些平台上
worklet 能解析却永远不注册自己的 processor，这条回落就是「麦克风能用」和「麦克风是死的」
之间的差别。

## 加载与测试

```bash
node --check clients/echoturn-client.js     # 只查语法
node --test "clients/tests/*.test.js"       # 行为
python -m pytest tests/test_client.py       # 同一批，从 Python 这侧
```

这些测试跑在 Node 上，不需要浏览器、不需要打包器。替身都在 `clients/tests/fakes.js` 里：
一个可以由测试往里推帧的麦克风、一个能回答那三条路由的 fetch、一个按「每取第 *n* 个采样」
渲染的离线音频上下文。
