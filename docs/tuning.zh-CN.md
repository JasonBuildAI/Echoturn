# 调参

**English: [tuning.md](tuning.md)** —— 英文版是唯一真源，本页是它的中文对照。
两版不一致时以英文版为准；改英文版时要同一个 commit 改这一页。

这个包里每一个阈值都是环境变量，而这些数字只写在 `echoturn.config` 的 `DIALS` 一处。
在供应商里或者在示例页里再抄一份，就是「其中一个过期了而所有东西看起来都正常」的成因 ——
所以示例页是从 `/config` 取整张表，而不是自己存一份。

它们在**被使用时**现读，而不是导入时读一次，所以改了配置对下一个请求就生效，不用重启。

```python
from echoturn.config import dials
dials()["vad_end_ms"]        # 现读
```

## 每一组是对着什么量出来的

### 识别

**16000 Hz** 是喂给语音模型的采样率，所以一段录音、一段重采样后的音频和一声 mock 蜂鸣，
在下游是可以互换的。

**用 `auto` 而不是写死语种。** 识别器一般能自己判断；而写死一个错的语种比不写更糟 ——
它会**信心十足地**转写成错误的语言，而不是报告自己不确定。

### 轮次结束

**打字 600 ms，通话里 700 ms。** 话说到一半的停顿比两条打字消息之间的停顿短，所以通话的
阈值更长。两者都是**兜底**：说完判定模型给的裁决会更早结束这一轮。

**最少 300 ms 人声。** 几十毫秒的敲桌子声，到了识别器那里会变成凭空冒出来的一个词。闸门的
依据是**人声长度**而不是音频长度，所以一段安静但里面真有一个词的录音仍然能过。

**判成「没说完」之后再等 800 ms。** 早一点结束是更小的错误：「没说完」判错，会让人对着一个
看着坏掉的东西说话；而「说完了」判错，他直接开口盖过去就行。

**300 ms 就把识别启动。** 等这一轮真的结束时，文本已经在路上了 —— 快速回复主要就靠这个。
它必须小于结束点，否则这一轮在「提前启动」变得有用之前就已经结束了。

关于 `speculate_ms` 与 `vad_end_ms` 这对参数，最要紧的一件事：**前者必须小于后者。**

### 打断

判据是 `max(barge_floor, echo * barge_ratio)`，且必须持续 `barge_ms`。三个数是因为它们回答
三种不同的坏情况：

* floor 挡住键盘、呼吸、撞桌子这些永远到不了 0.10 的声音；
* ratio 挡住从麦克风回来的回复 —— 忽略 ratio 的外放，会在每条回复说到一半时打断自己；
* 时长挡住一把椅子或一扇门产生的那一帧孤立的大声。

`barge_ratio` 太低，外放的人声就盖不过回复；`barge_ms` 太低，两人就会不停地互相打断。
这里的取值是**戴着耳机和开着外放各用一遍**得到的。

### 攒句合成

取舍是「能听见的接缝」对「延迟」。一句话一次请求会在句子之间留下接缝，因为每次请求都从零开始
自己的语调；而等更多文本进来，代价就是首声延迟。

**第一片有它自己小得多的阈值** —— 7 个字符对 36 个 —— 因为听者判断快慢几乎全看第一声。
通话中还要更小（5），因为一轮语音通常只有一两句，而一个很短的首片造成的接缝，在电话里没人
会注意到。

那些 `_MIN` 值是各自的下限：比它短的片不值得花一次请求，于是攒句器继续攒。

#### 什么算一个结尾

句子切在 `。`、`！`、`？`、`!`、`?`；逗号、冒号、分号、省略号只有在缓冲区长到值得发出去时
才成为切点。**ASCII 句点不是结尾**，对英文回复来说这是个真实的限制：一整段带句点的英文，
会作为一整片到达，只发一次合成请求。

这是这个库**被抽出来时就有**的行为，不是在这里做的决定，所以它是被写下来而不是被顺手改掉 ——
上面那些阈值都是对着它量出来的，放宽结尾集合会让这一页上的每个数字都变。
`tests/test_text_sentences.py` 把两个方向都钉住了：一条测会切的结尾，一条测不会切的那个。

### 合成并发

**32 个在飞，进程级。** 它是按「供应商能容忍多少并发」定的，不是按有多少人在说话。一轮一个
线程池，在五百路同时通话时会往机器上放一千五百条线程，而大家等空闲核心的时间，就是大家什么
都听不到的时间。

它在**建池时**读一次，也就是每进程一次，所以改它要重启。这是这一页里唯一需要重启的设置。

### 上下文空档

**600 秒。** 在它之内，对话继续；超过它，模型从头开始，token 省下来。

它不影响别的东西。聊天记录、转写、以及宿主存的任何东西都不受它影响，而系统里这样的时钟
**只有一个**。再来第二个空闲概念 —— 「窗口重开了」和「回复形态重置了」当成两个计时器 ——
就是两者对同一段静音给出不同说法的成因。

## 非法取值

读不出来的值回落到默认值，而绝不会回落到别的什么。`ECHOTURN_BARGE_RATIO=3,5` 得到的是 3.5，
也就是发布时的比例 —— 绝不会是 0，那会让麦克风里任何一点声音都变成打断。它还会**说一声**：
`echoturn.config` 这个 logger 上打一行，点明变量名、读不出来的原值、以及实际按下的默认值 ——
每个名字每进程只打一次，因为每来一个请求就重复刷的告警等于没有告警。「看着改了、跑的却还是
老数字」这种问题除了行为之外没有任何症状，是最贵的一类 bug。

`ECHOTURN_VAD_ENGINE` 是唯一一个有固定取值列表的设置。不在列表里的名字会变成 `silero`，
因为这条代码跑在实时对话的路径上，而配置文件里的一个错字不该让声音停下 —— 这一行同样会点
出变量名，理由和上面一样。

**空值**不算错：它等于没设置，静默取默认值。配置文件里一行 `ECHOTURN_TTS_PROVIDER=` 的
意思是「用默认值」；而一个把空字符串照单全收的工厂，会报出一个叫 `""` 的未知供应商 ——
从外面看，那就是「它不说话了，而没人改过任何东西」。

## 换一个麦克风就要换一组数字

默认值是对着**一套**环境定的。换一个房间、一支麦克风、一种口音，通常就差其中一个值，这也是
它们被做成设置而不是常量的原因：

* 老被人抢话 → 调大 `barge_ms` 或 `barge_ratio`；
* 打断不了 → 调小 `barge_ratio`；麦克风本身很轻就再调小 `barge_floor`；
* 一句话还没说完回复就来了 → 调大 `vad_end_ms`；
* 回复开头感觉慢 → 调小 `tts_first_chars`（代价是更多请求、更多接缝）。
